# Confidants – Project Structure & Architecture Log

## Project Mission
**Confidants** is an offline-first, privacy-focused mobile application (Android & iOS) that ingests device contacts, constructs rich personal profiles (including birthdays, optional nicknames, preferences, and dynamic key-value attributes), exports SHA-256-indexed JSON sub-files for local mini-LLM ingestion, and provides an opt-in conversational chat interface to query accumulated personal context without external state management libraries or cloud exposure.

## File Breakdown

### Root Configuration
- `pubspec.yaml`: Declares Flutter SDK constraints and core offline dependencies (`flutter_localizations`, `intl`, `lucide_icons_flutter`, `sqflite`, `path`, `path_provider`, `crypto`, `flutter_contacts`, `shared_preferences`, `local_auth`).
- `project-structure.md`: Living architecture reference tracking completed chunks, individual file responsibilities, and LLM integration instructions.
- `l10n.yaml`: Localization generator config (ARB dir `lib/l10n`, template `app_en.arb`, non-nullable `AppLocalizations`).
- `lib/main.dart`: Application entry point. Registers localization delegates + `AppLocalizations.supportedLocales`, initializes `PreferencesService`, reconciles exported AI context chunks via `ExportService.instance.syncAll()`, listens reactively to `isDarkModeNotifier`, and launches `AuthGuardScreen`.

### Localization (`lib/l10n/`)
- `lib/l10n/app_en.arb`: Template (English) with every user-facing string, including placeholders and plurals. **No string literals are allowed in UI code; add a key here instead.**
- `lib/l10n/app_tr.arb`: Turkish translations of every key in `app_en.arb`. To add a language, add `app_<code>.arb` and run `flutter pub get`.
- `lib/l10n/app_localizations*.dart`: Generated by `flutter pub get` (do not edit).
- Const named constructors can't read a `BuildContext`, so they store `L10nText` tear-offs (e.g. `CustomAppBar.chat`, `SettingsToggleTile.aiOptIn`, `ModelOptionTile.qwen`, `_ProfileField.nickname`) that are resolved with the active `AppLocalizations` in `build`.

### Data Models (`lib/data_models/`)
- `lib/data_models/ai_model_config.dart`: Encapsulates swappable local LLM configurations with preset named constructors (`AiModelConfig.smolLm2`, `AiModelConfig.qwen25HalfB`, `AiModelConfig.llama32OneB`, `AiModelConfig.qwen25OneHalfB`, `AiModelConfig.llama32ThreeB`). Isolates model metadata and URLs so adding, removing, or replacing default models requires no UI or service rewrites.
- `lib/data_models/user_profile.dart`: Core entity representing a person's profile (`id`, `profileHash`, `name`, `phoneNumber`, `email`, `birthday`, optional `nickname`, `notesToRemember`, `likes`, `dislikes`, `hobbies`, `isTrainingEnabled`, timestamps, and linked `CustomField` list). Includes named constructors (`UserProfile.fromContact`, `UserProfile.empty`, `UserProfile.fromMap`), SQLite serialization (`toMap`), and privacy-preserving LLM chunk serialization (`toExportJson`).
- `lib/data_models/custom_field.dart`: Dynamic key-value attribute attached to a profile (`id`, `profileId`, `fieldKey`, `fieldValue`). Provides `CustomField.draft` and `CustomField.fromMap` named constructors plus SQLite and export map helpers.
- `lib/data_models/contact_item.dart`: Lightweight transfer model representing an imported device address book entry (`displayName`, `phoneNumber`, `email`) with `ContactItem.phoneOnly` and `ContactItem.fromMap` named constructors.
- `lib/data_models/chat_message.dart`: Conversational message model (`id`, `message`, `sender`, `timestamp`, `isGenerating`, `isError`) with `ChatMessage.user` and `ChatMessage.ai` named constructors for semantic instantiation.

### Services (`lib/services/`)
- `lib/services/ai_service.dart`: Orchestrates local mini-LLM context assembly and query execution. Reads exported `.json` chunks from `ExportService`, builds the system prompt, resolves the active `AiModelConfig` from `PreferencesService`, and exposes the standardized `// TODO: AI API call` boundary alongside an offline in-context matcher for immediate testing.
- `lib/services/preferences_service.dart`: Singleton wrapper over `SharedPreferences` persisting `is_dark_mode`, `require_fingerprint_lock`, `is_ai_enabled` (AI opt-in), `selected_ai_model`, and `custom_ai_model_path`. Exposes `ValueNotifier` streams for zero-dependency reactive UI updates.
- `lib/services/auth_service.dart`: Singleton biometric authentication service built on `local_auth`. Verifies hardware biometric/credential availability and triggers the native OS unlock prompt with graceful `PlatformException` handling.
- `lib/services/contact_service.dart`: Device address book service using `flutter_contacts`. Requests read-only contact permissions and extracts normalized `ContactItem` entries.
- `lib/services/hash_service.dart`: Stateless SHA-256 cryptographic utility (`crypto` package). Normalizes phone numbers/identifiers into deterministic hashes (`hashIdentifier`) and calculates payload checksums (`computeChecksum`) for exported JSON chunks.
- `lib/services/export_service.dart`: Singleton exporter writing one pretty-printed JSON chunk per training-enabled profile to `<app documents>/ai_context_chunks/<profile_hash>.json` (phone number omitted, filename is the SHA-256 hash). `syncProfile` skips rewrites when the stored checksum matches and removes the chunk when training is disabled; `removeProfileChunk` deletes file + mapping; `syncAll` reconciles the folder with the database at startup; `listChunkFiles` provides the context files to `AiService`.
- `lib/services/database_helper.dart`: Singleton SQLite manager (`sqflite`) initializing `confidants.db` with `PRAGMA foreign_keys = ON` and managing three tables: `profiles`, `custom_fields` (with `ON DELETE CASCADE`), and `file_mappings`.

### Frontend Theme (`lib/frontend/theme/`)
- `lib/frontend/theme/app_colors.dart`: Single source of truth for the minimalist Black (`#0A0A0A`), White (`#F8F9FA` / `#FFFFFF`), and Dark Blue (`#0D1B2A`, `#1B263B`, `#415A77`, `#778DA9`) palette. Prevents raw hex codes across UI files.
- `lib/frontend/theme/app_theme.dart`: Configures Material 3 `lightTheme` and `darkTheme` (`ThemeData`) using `AppColors` for surfaces, cards, inputs, dividers, and bottom navigation.

### Frontend Shared Utilities (`lib/frontend/util/`)
- `lib/frontend/util/l10n_extensions.dart`: `L10nText` typedef and `context.l10n` shortcut for `AppLocalizations.of(context)`.
- `lib/frontend/util/proteinbar.dart`: Custom blurred overlay toast notification (`proteinBar`) replacing standard Flutter `SnackBar` throughout the application.
- `lib/frontend/util/custom_app_bar.dart`: Shared header widget with semantic named constructors (`CustomAppBar.chat`, `CustomAppBar.profiles`, `CustomAppBar.settings`, `CustomAppBar.detail`) that pre-populate Lucide icons, titles, and subtitles.
- `lib/frontend/util/contact_picker_dialog.dart`: Searchable modal bottom sheet (`ContactPickerDialog.show`) for selecting an imported `ContactItem` from the device address book.
- `lib/frontend/util/auth_guard_screen.dart`: Startup security gate that checks `require_fingerprint_lock`. Immediately enters `NavigationShell.chat` if disabled, or presents a biometric unlock prompt and locked vault barrier (`LucideIcons.fingerprint` / `LucideIcons.shieldAlert`) until verified.
- `lib/frontend/util/navigation_shell.dart`: Persistent 3-tab `BottomNavigationBar` scaffold (`Chat`, `Profiles`, `Settings`) using `IndexedStack` and named constructors (`NavigationShell.chat`, `NavigationShell.profiles`, `NavigationShell.settings`).

### Frontend Pages (`lib/frontend/`)
- `lib/frontend/chat_page/chat_page.dart`: Conversational AI interface gated by the user's `isAiEnabled` opt-in setting. Uses `_ChatStateView.optInRequired` and `_ChatStateView.ready` preset named constructors, renders `ChatBubble.user` / `ChatBubble.ai` items, and dispatches queries to `AiService`.
- `lib/frontend/chat_page/util/chat_bubble.dart`: Message bubble widget with `ChatBubble.user` and `ChatBubble.ai` named constructors, generation spinner, error state, and timestamps.
- `lib/frontend/chat_page/util/chat_input_bar.dart`: Bottom message composer with send button (`LucideIcons.sendHorizontal`) and busy state lock while generating.
- `lib/frontend/profiles_page/profiles_page.dart`: Searchable list of personal profiles with contact import (`ContactPickerDialog`), manual profile creation, and preset empty-state named constructors (`_ProfilesEmptyState.initial`, `_ProfilesEmptyState.search`).
- `lib/frontend/profiles_page/profile_detail_page.dart`: View, create (`ProfileDetailPage.create`), edit (`ProfileDetailPage.edit`), and delete individual profiles with `proteinBar` notifications; saving or deleting triggers `ExportService`.
- `lib/frontend/profiles_page/util/profile_card.dart`: Reusable profile summary card with `ProfileCard.compact` (for list items) and `ProfileCard.detailed` (for detail headers showing SHA-256 hash, birthday, and custom attribute count) named constructors.
- `lib/frontend/profiles_page/util/profile_form.dart`: Comprehensive profile form featuring native birthday date-picker, `SettingsToggleTile.training`, and extracted `_ProfileField` preset named constructors (`.name`, `.nickname` (optional), `.phone`, `.email`, `.notes`, `.likes`, `.dislikes`, `.hobbies`).
- `lib/frontend/profiles_page/util/custom_field_editor.dart`: Dynamic key-value row editor for adding, updating, and removing arbitrary custom profile attributes.
- `lib/frontend/settings_page/settings_page.dart`: Settings screen wrapping Dark Mode (`SettingsToggleTile.theme`), Biometric Launch Lock (`SettingsToggleTile.biometrics`), Local AI Opt-In (`SettingsToggleTile.aiOptIn`), and—when AI is enabled—the model dropdown & hardware warning card (`ModelSelectorCard` + `ModelWarningCard`).
- `lib/frontend/settings_page/util/settings_toggle_tile.dart`: Reusable preference switch card with preset named constructors (`SettingsToggleTile.theme`, `SettingsToggleTile.biometrics`, `SettingsToggleTile.training`, `SettingsToggleTile.aiOptIn`).
- `lib/frontend/settings_page/util/model_selector_card.dart`: Dropdown model selector (`ModelSelectorCard`) showing storage and RAM specs inside each dropdown option, paired with a contextual hardware warning card below (`ModelWarningCard.smolLm2`, `.qwenHalfB`, `.llamaOneB`, `.qwenOneHalfB`, `.llamaThreeB`).

## Connecting the Local LLM Inference Engine
1. **Where to Plug In**: Open `lib/services/ai_service.dart` and locate the `// TODO: AI API call` block inside `generateResponse()`.
2. **Inputs Already Prepared for You**:
   - `model` (`AiModelConfig`): Contains `model.id`, `model.displayName`, `model.defaultFileName`, `model.downloadUrl`, and `model.customFilePath` (when the user selects their own `.gguf` file in Settings).
   - `contextChunks` (`List<File>`): The raw `.json` files exported in `/ai_context_chunks/<sha256>.json`.
   - `systemPrompt` (`String`): The pre-assembled system prompt containing all training-enabled JSON profile chunks.
   - `userQuery` (`String`): The user's question from the Chat UI.
3. **Swapping or Removing Default Models**:
   - Edit `lib/data_models/ai_model_config.dart` to change `AiModelConfig.qwen25HalfB()` or add new named constructors, without touching `ChatPage` or `ExportService`.
